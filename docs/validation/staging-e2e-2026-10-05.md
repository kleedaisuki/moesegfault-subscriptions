## Defects exposed and repaired

### Registration lifetime and continuation

The original Identity anonymous browser binding and OAuth transaction lasted five
minutes, while mailbox challenges/proofs lasted ten. Password signup also lost
the pending Subscribe OAuth continuation. The approved repair renews the same
browser binding only to the validated proof deadline, aligns only live pending
OAuth context, and atomically binds the new principal/session to that transaction.
Subscribe's bounded preauthentication deadline was aligned. Exact registered
redirects, PKCE, state, nonce, token verification, browser binding and single-use
proofs remain enforced. Fresh Beta's automatic hosted callback verifies the
user-facing result beyond local regression tests.

### Return navigation after reload

The portal gated Return to app on ephemeral activation-success React state.
Reloading removed the link despite the authorized continuation retained by the
BFF. Final 0e2b892 renders the validated server continuation without requiring a
just-completed activation. The HTTPS guard remains; untrusted query parameters
do not become navigation authority. Hosted reload and actual link click verified
this repair.

### Mail retrieval harness correction

The first administrator-mail query was unbounded and returned only an older
matching email. Private comparison confirmed the prepared code was A's consumed
code. Rejection was expected and preserved cross-principal isolation. The new
message was retrieved by exact summary ID with received time
`2026-10-04T17:31:30.700Z`, instead of the older `2026-10-04T16:03:54.752Z`.
The original issuance intent was resumed; no new UUID or duplicate issuance was
created to conceal the harness error.

Reusable rule: bound search with `--after <issuance-UTC>`, verify received time,
and retrieve the exact intended message ID. A newly accepted send need not appear
in the first query immediately. The mail body has no issuance-intent ID; do not
claim an absent correlation field.

## Reproduction and private-data boundary

1. Sign out only the previous synthetic staging principal in Account and Subscribe.
2. Begin a fresh Subscribe request with a permitted Account return.
3. Register a fresh owned alias and request its mailbox proof. Retrieve using:

   ```powershell
   amail search --to <owned-test-alias> --after <request-UTC> --limit 2 --wait-seconds 20
   amail read <exact-message-id> --out .temp/acceptance/<new-private-archive> --unpack
   ```

4. Submit proof and protected random new password through Login UI. Assert
   automatic authenticated Subscribe navigation.
5. Save recognizable billing details. Issue once with
   `node scripts/admin-issue.mjs --plan platform-monthly`; retain the intent and
   use `--resume <same-intent>` to recover unknown outcomes.
6. Retrieve the correct administrator email with bounded received timestamp,
   privately extract its explicit activation field and redeem through UI.
7. Reload; assert profile/Active subscription persist and Return to app remains.
8. Click Return to app; verify actual Account principal and embedded subscription.
   If access expires during testing, use ordinary SSO.
